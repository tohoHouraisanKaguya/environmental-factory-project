## 项目目标

按照任务书和教案要求，完成污水处理厂课程设计。项目采用“分项推进、逐项提交、自动自审”的方式：每个计算项目形成独立提交和 PR；检查通过且与最新 `main` 无冲突时直接合并，再进入下一项目。


## 快速开始

开始工作前，请按以下顺序阅读：

1. [`任务日志/README.md`](任务日志/README.md)：先读取最新一份任务日志，了解上一轮实际完成项、核验结果和待办；
2. [`AGENTS.md`](AGENTS.md)：Agent 协作规范和修改边界；
3. [`hand_off.md`](hand_off.md)：当前交接状态、已通过口径和下一步任务；
4. [`计算成果/提交版/修改与核验说明.md`](计算成果/提交版/修改与核验说明.md)：最新整体成果的口径、核验和待确认事项；
5. [`计算成果/计算进度.md`](计算成果/计算进度.md)：各计算项目的历史进度；
6. [`计算项目大纲_待确认.md`](计算项目大纲_待确认.md)：项目顺序和成果要求；
7. [`资料索引/阅读索引.md`](资料索引/阅读索引.md)：原始资料、页码映射和查阅顺序；
8. 禁止直接向 `main` 分支提交修改。

  所有改动必须：

  1. 创建独立分支
  2. 完成修改
  3. Push 到远端
  4. 创建 Pull Request
  5. 自审并核对最新 main；无冲突且检查通过时直接合并

## 计算成果写作要求

每个项目按以下顺序组织：

1. 参数及依据；
2. 公式与符号；
3. 数值代入；
4. 取整或设备选择；
5. 工况校核；
6. 结果表、流程图或草图；
7. 待审核事项。

引用原始资料时，尽量注明文件名、书内页码、PDF 页码、表号或条款，并区分题设原始数据、已通过口径、工程假定和待补数据。

## Agent 和小组协作

- 一次只推进一个计算项目。
- 当前项目完成自审并合并后，自动开始下一个项目，无需等待用户逐项确认。
- 开始修改前检查 `git status`，避免覆盖他人的未提交修改。
- 一个提交尽量只对应一个逻辑任务，不混入无关格式化。
- 优先使用分支和 Pull Request 协作，避免直接覆盖他人的工作。
- 不使用强制推送，不执行 `git reset --hard`，不批量删除他人文件。
- 不提交 Token、密码、Cookie、临时文件或个人本机敏感路径。

详细规则见 [`AGENTS.md`](AGENTS.md) 和 [`CONTRIBUTING.md`](CONTRIBUTING.md)。

## 审核与交接

完成一个项目后，应同步更新 `计算成果/计算进度.md`，执行自审和冲突检查，并在回复或 PR 描述中说明：

- 修改了哪些文件；
- 使用了哪些依据和假定；
- 如何进行验证；
- 哪些假定需要在后续项目闭合或复核。

检查通过且与最新 `main` 无冲突时，PR 直接合并。只有出现冲突、必需检查失败、敏感信息、不可逆操作或会使当前成果失效的高风险问题时，才暂停并请求人工处理。历史文件名中的“待审核”用于保持链接稳定，不代表必须等待逐项批准。
